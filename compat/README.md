# Тесты совместимости с Hermes

Прогоняют **наш** `AliceAdapter` внутри настоящего `GatewayRunner` Hermes на закреплённой ревизии
([совместимость](../docs/compatibility.md)): плагин ставится копией в `plugins/`, шлюз грузит его через `discover_plugins`, запрос Алисы идёт по
HTTP в loopback-listener, агент — скриптованный LLM из `tests/fakes` Hermes (ни модели, ни ключей, ни расходов). Telegram
(группа `T`) — поддельный Bot API `TelegramStandin` оттуда же.

Тестовая обвязка Hermes (`gateway.run`, `tests.fakes.*`) — не публичный API плагинов; в `compat/` и `prototypes/` она разрешена,
в `yandex-alice/` — нет.

| Группа | Что проверяет |
|---|---|
| `P` | `validate_plugin_dir` манифеста, регистрация платформы (`source`, `display_tier`, `allowed_users_env`) |
| `A` | текст, инструмент, пустой ответ модели и сбой провайдера → «не получилось», уведомление «📬» не озвучивается, порядок start → итог → complete |
| `B` | вторая фраза в занятую беседу не доходит до Hermes, гейт Р2, хук `on_processing_complete` после итога |
| `G` | гейт Р2 при пропаже `on_processing_complete`: итог без complete; потерянные итог и complete — ход снят тиком по сроку |
| `Q` | фраза в занятую сессию после срока потерянного хода, `queue` (известное ограничение): оба итога поздние, в Telegram |
| `I` | то же при `interrupt` (режим боевого сервера, известное ограничение, HERMESYAND-26): ответ в Telegram, вопрос не закрывается |
| `H` | «повтори» из `state.db` профиля-цели маршрута (A2, симлинк): обычный ход, инструмент, `(empty)`, сбой провайдера, новый диалог, время чтения |
| `N` | то же без маршрута (профиль по умолчанию) |
| `Z` | «повтори» после сжатия беседы на месте |
| `L` | один listener (старт, reload, переподключение шлюзом, остановка), исключение обработчика, занятый порт и самоподключение, секрета нет в логах |
| `R` | перезапуск шлюза посреди хода (штатный и SIGKILL), леджер «♻️» и строка `pending` без пометки (в Telegram, не голосом), рестарт в простое, новая фраза во время дозапущенного хода |
| `T` | SIGKILL посреди ожидания подтверждения: команда не выполнена, старая карточка «неактуальна», новая карточка |

Группы `L`, `R`, `T` запускают шлюз **дочерним процессом** (`gateway_child.py`, `restart.py`): его останавливают штатно или
убивают (`SIGKILL` — только ему) и стартуют заново в том же доме; каждая сцена — свой дом (`<корень прогона>/scenes/<имя>`).
Изоляция `run.sh` сохраняется: дочерний процесс наследует `env -i`-окружение, при EOF на stdin выходит сам.

Подтверждённые результаты и границы покрытия — в [документации по совместимости](../docs/compatibility.md#ограничения).

## Запуск

```sh
bash compat/run.sh <hermes-checkout> <hermes-python> <P|A|B|G|Q|I|H|N|Z|L|R|T>
```

- `<hermes-checkout>` — git checkout Hermes на ревизии из `docs/compatibility.md`.
- `<hermes-python>` — `python` окружения зависимостей Hermes. На установленном Hermes это
  `<HERMES_HOME>/installs/<key>/environments/<generation>/venv/bin/python` (интерпретатор из `hermes --print-runtime-command`
  не годится: при временном `HERMES_HOME` он не находит закоммиченное окружение). В CI — `python` из `uv sync`.
- Скрипт сам создаёт временный каталог `hya-compat-*` (HOME, `HERMES_HOME`, блокировки), запускает под `env -i`, `timeout`, `nice`,
  `choom` (при нехватке памяти ядро убьёт прогон, а не живой шлюз) и удаляет каталог при выходе. Настоящий `HERMES_HOME` не
  используется. Каждая группа — отдельный процесс: пиковый RSS ~100 МБ (P) и ~250–290 МБ (остальные); время: P 5 с, G, N, Z, T
  15–40 с, A, H, R ~1–1,5 мин, L ~2,5 мин (в нём ожидание повторной попытки шлюза).
- Пропущенный тест или ноль запущенных — выход 1. Без checkout или с неверным python — выход 2.
- Каталог лежит вне `tests/`, поэтому `python -m unittest discover -s tests` его не собирает.
- В выводе групп с рестартами бывает `BrokenPipeError` в потоке поддельного LLM (поток мёртвого запуска пишет в закрытое
  соединение) — на результат не влияет.
