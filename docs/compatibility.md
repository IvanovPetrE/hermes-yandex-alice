# Совместимость с Hermes Agent

Плагин опирается на публичный API Hermes (`website/docs/developer-guide/plugins/public-api.md`) и на ряд
внутренних поведений шлюза (итоги ходов, хуки обработки, перезапуск посреди хода). Тесты совместимости
запускаются против checkout Hermes на **закреплённой ревизии**; пропущенный тест не считается пройденным.

## Закреплённая ревизия

| Параметр | Значение |
|---|---|
| Репозиторий | `https://github.com/NousResearch/hermes-agent.git` |
| Тег | `v0.23.2` |
| Коммит | `ae2a81ccc00e9b7c06301523e5bb09608397149c` |
| Python | `>=3.11,<3.15` (диапазон Hermes) |

Обновление ревизии — осознанное действие: сменить тег и коммит здесь и в `.github/workflows/tests.yml`, прогнать тесты
совместимости, разобрать расхождения, затем править плагин. Манифест плагина требует `requires_hermes: ">=0.23.1"`; тесты
совместимости на v0.23.1 не гонялись (до 2026-11-18 закреплена была она, поэтому версия плагина допускает её, но не проверена).

## Что проверяют тесты совместимости (`compat/`)

Наш адаптер работает внутри настоящего `GatewayRunner`, агент — скриптованный LLM из тестов Hermes. Проверено на v0.23.2:

- регистрация платформы (`register_platform`) через настоящий `discover_plugins` и валидация манифеста (`validate_plugin_dir`);
- итог хода приходит в `send()` с `reply_to` хода и `notify=True`, один на ход, до `on_processing_complete` (S1);
- ход с инструментом: промежуточное «Сейчас проверю.» итогом не становится;
- пустой ответ модели и сбой провайдера озвучиваются как «Не получилось, попробуйте ещё раз.»;
- уведомление «📬 No home channel» приходит в `send()` и не озвучивается;
- вторая фраза в занятую беседу не доходит до Hermes (гейт Р2), шлюзу не передаётся фраза при открытом ходе.

**Ещё не покрыто** (следующий срез этапа 6): исключения занятой сессии и дозапуск хода после перезапуска
(`interactive_resume`, S5), гейт Р2 при пропаже `on_processing_complete`, чтение истории (`hermes_state`) для «повтори» (S7).

## Как запускать

Подробности — `compat/README.md`.

```sh
bash compat/run.sh <hermes-checkout> <hermes-python> <P|A|B>
```

- **Сервер с Hermes:** checkout — `~/.hermes/hermes-agent` на нужном теге, `python` — окружения зависимостей в
  `~/.hermes/installs/<key>/environments/<generation>/venv/bin/python`. Прогон идёт во временном каталоге и не трогает живой шлюз.
- **CI:** job `compat` в `.github/workflows/tests.yml` клонирует ревизию из таблицы выше, проверяет коммит, ставит зависимости
  `uv sync --locked --python 3.14 --extra all` (команда Hermes сокращена: у них больше extras) и гоняет группы `P`, `A`, `B`.
  **Job не запускался** (репозиторий ещё не опубликован) — проверка на этапе 9; не проверено, что
  `import hermes_bootstrap` работает в venv, созданном `uv sync`, а не в закоммиченном окружении установленного Hermes.
- Группа `A` занимает около минуты и ~270 МБ памяти; прогон нужен после каждого обновления Hermes (`hermes update`).
