# Совместимость с Hermes Agent

Плагин опирается на публичный API Hermes (`website/docs/developer-guide/plugins/public-api.md`) и на ряд
внутренних поведений шлюза (итоги ходов, хуки обработки, перезапуск посреди хода). Тесты совместимости
запускаются против checkout Hermes на **закреплённой ревизии**; пропущенный тест не считается пройденным.

## Закреплённая ревизия

| Параметр | Значение |
|---|---|
| Репозиторий | `https://github.com/NousResearch/hermes-agent.git` |
| Тег | `v0.23.1` |
| Коммит | `3b421578588243f920886e6fe79a6faa87ea026e` |
| Python | `>=3.11,<3.15` (диапазон Hermes) |

Обновление ревизии — осознанное действие: сменить тег и коммит здесь, прогнать тесты совместимости, разобрать
расхождения, затем править плагин.

## Что проверяют тесты совместимости (план, этап 6)

Закреплённые случаи из проб S1–S7 (`docs/RECON.md`):

- итог хода приходит в `send()` с `reply_to` и `notify` (S1);
- хук `on_processing_complete` вызывается после итога; гейт Р2 не зависает при его пропаже (S5);
- исключения занятой сессии и дозапуск хода после перезапуска (`interactive_resume`, S5);
- чтение истории (`hermes_state`) для «повтори» (S7);
- регистрация платформы (`register_platform`) и валидация манифеста (`hermes plugins validate`).

## Как запускать

Статус: **не реализовано**. Тесты будут клонировать ревизию из таблицы выше (в CI) или брать локальный checkout
по пути из переменной окружения; без checkout они помечаются как пропущенные и в итог не засчитываются.
