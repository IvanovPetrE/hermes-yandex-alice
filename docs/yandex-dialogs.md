# Навык в Яндекс Диалогах

Навык приватный (виден только вашему аккаунту), один владелец. Консоль: `https://dialogs.yandex.ru/developer`.

## Создание навыка

1. «Создать диалог» → «Навык в Алисе».
2. Основная информация: название и фразы активации — на ваше усмотрение (например «Спроси у Моего Секретаря…»).
3. Backend → **Webhook URL**: `https://alice.example.org/alice/<ALICE_PATH_SECRET>` (домен и секрет — ваши; секрет
   в URL — тот же, что в `.env`). Прокси срезает префикс `/alice`, плагин сверяет остаток пути с секретом.
4. Права доступа: приватный навык; доступ только владельцу.
5. Интенты (ниже), затем «Тестирование» → «Сохранить» → «Отправить на модерацию» → «Опубликовать».

`session.user.user_id` владельца виден в блоке «Последний запрос» чата «Тестирование» (`session.user.user_id`) и в
теле запроса приложения Алисы. Впишите его в `ALICE_OWNER_USER_ID` и перезапустите шлюз. Пока переменная пуста,
плагин работает в режиме привязки и отвечает всем «навык ещё не привязан» (в этом режиме `user_id` пишется в лог
шлюза — единственный ID, который плагин когда-либо логирует). У консольного тестера и у реального
устройства `user_id` могут различаться, ориентируйтесь на реальное устройство.

Имейте в виду: чат «Тестирование» в консоли Диалогов не всегда обращается к вашему webhook (интенты в нём
проверяются, но ответ может прийти не от плагина). Реальную работу проверяйте в приложении Алисы или на колонке.

## Интенты `hya.*`

Плагин смотрит `request.nlu.intents` и реагирует на семь своих интентов; кроме них учитываются системные
`YANDEX.CONFIRM`, `YANDEX.REJECT`, `YANDEX.HELP`, `YANDEX.REPEAT`.

| Интент | Смысл |
|---|---|
| `hya.wait` | «подожду»: ждать ответ в том же запросе |
| `hya.later` | «позже»: ответ заберу потом |
| `hya.answer.get` | «скинь ответ»: озвучить готовый ответ |
| `hya.telegram` | «пришли в Телеграм»: итог отправить в Telegram |
| `hya.dialog.new` | «новый диалог»: начать беседу заново |
| `hya.dialog.continue` | «прошлый»: продолжить прошлую беседу |
| `hya.next` | «дальше»: следующая часть длинного ответа |

### Формат грамматик в консоли

Скобочные конструкции в этой консоли надёжно не разбираются. Рабочий вариант — режим `%exact` и одна фраза на строку
(`root:` в начале). Исключение — компактная грамматика `hya.dialog.continue` ниже: она тоже проходит тест, но
проверьте её кнопкой «Протестировать» (точность и полнота должны быть 100%).

В каждом интенте заполните «Положительные тесты» и «Отрицательные тесты»: вход «Протестировать» покажет пересечения
с соседними интентами. Не оставляйте старые интенты прежнего решения: они перекрывают `hya.*`.

### Образцы

`hya.wait`:
```
root:
%exact
подожду
я подожду
подождем
подождём
жду
я жду
ждем
ждём
буду ждать
я буду ждать
могу подождать
подожду ответ
жду ответ
я подожду ответ
```

`hya.later`:
```
root:
%exact
позже
потом
попозже
я спрошу позже
спрошу позже
спрошу потом
я спрошу потом
заберу позже
заберу потом
узнаю позже
давай потом
```

`hya.answer.get`:
```
root:
%exact
скинь ответ
скинь мне ответ
дай ответ
дай мне ответ
давай ответ
скажи ответ
озвучь ответ
зачитай ответ
```

`hya.next`:
```
root:
%exact
дальше
далее
читай дальше
читай далее
давай дальше
давай далее
говори дальше
зачитай дальше
следующая часть
следующую часть
давай следующую часть
```

`hya.dialog.continue`:
```
root:
    (продолжить|продолжим|продолжи|давай)? (прошлый|прошлую|предыдущий|предыдущую) (диалог|разговор|тему|тема)?
```

`hya.dialog.new` и `hya.telegram` составьте так же списком фраз. Примеры: для `hya.dialog.new` — «новый диалог»,
«новый», «начать заново», «хочу новый диалог»; для `hya.telegram` — «пришли в телеграм», «отправь в телеграм»,
«в телеграм». Сразу проверьте их тестом и на пересечения.

## Проверка

В «Тестировании» (черновик) отправляйте по одной фразе и смотрите блок «Последний запрос» → `request.nlu.intents`:
должен быть ровно ожидаемый `hya.*` (системные `YANDEX.BOOK.*` рядом допустимы). После публикации повторите на
опубликованной версии: черновик и опубликованная версия — разные.
