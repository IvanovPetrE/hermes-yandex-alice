# Прототип S7: `hermes_state` как источник «повтори»

Этап 1, S7 (`docs/PLAN.md`). Отвечает на вопрос: может ли адаптер этапа 3 **в процессе шлюза** (область профиля по
умолчанию), только через публичный API, найти голосовую беседу **целевого профиля** по `chat_id` и прочитать последний
ответ агента с текстом — после обычного хода, хода с инструментом, сжатия контекста и перезапуска шлюза — и уложиться в
бюджет ~3,5 с. Вердикт и выводы — `docs/RECON.md`, «S7».

## Что внутри

- `plugin/` — **модель адаптера** `yandex-alice-s7` (находится штатным обнаружением Hermes). Импортирует только модули
  из `public-api.md`, `os.environ` не читает. HTTP-входа нет (его проверила S5): ходы и чтения проба подаёт
  командами дочернему процессу.
  - `__init__.py`: журнал хода в файл (метаданные и первые символы синтетического текста), правило итога S1
    (`recovery.classify_send`), `hold_final` (отправка итога зависает — проба убивает шлюз, как S5 R3),
    `probe_recall` — чтение истории в рабочем потоке под сроком (`asyncio.wait_for`), форма `RecallLast` → `Recalled`.
  - `history.py` — чтение: маршруты `load_gateway_config()` → профиль → дом (`hermes_constants`) →
    `SessionDB(read_only=True)` → `find_session_by_origin` → `resolve_resume_session_id` → `get_messages` порциями.
    Чистые функции (`last_answer`, `read_tail`, `pick_profile`) — без Hermes; импорты Hermes ленивые. Одно чтение за раз
    (`busy`, если предыдущее не закончилось), `SessionDB` закрывается в `finally`.
  - `recovery.py` — копия из S5 (правило итога и срез пометки леджера).
- `probe_s7.py` — обвязка: `HistoryTests` (без Hermes) и группы A–C. Проба держит скриптованный LLM Hermes, шлюз
  запускает **дочерним процессом** (`probe_s7.py child`): настоящий `GatewayRunner` (мультиплекс default + `p2`, маршрут
  `yandex_alice → p2`; группа C — без маршрута). «Перезапуск» — новый дочерний процесс в том же доме (штатная остановка
  или `SIGKILL`). Команды ребёнку — JSON-строки в stdin. Сверку `state.db` целевого профиля проба делает сама
  (`mode=ro`), только чтобы сравнить с прочитанным плагином.
- `run.sh` — запуск во временном `HOME`/`HERMES_HOME`/`TMPDIR`/lock, `env -i`, `timeout 1500`, `nice`, `choom`; сторож
  памяти считает пробу и всех живых детей вместе (`S7_RSS_LIMIT_MB=450`, выход 137).

Группы: A — `HistoryTests` + сцены A0–A9 (неизвестная беседа; обычный ответ; ход с инструментом: итог, а не комментарий;
формат «ГОЛОС/ТЕЛЕГРАМ»; пустой ответ модели; новая беседа; сжатие; время холодных и тёплых чтений; чтение во время хода и
при блокировке записи; сбои — неверный профиль, срок 1 мс, шторм таких чтений, число потоков и файлов до/после);
B — перезапуски: B1 штатный в простое, B2 штатная остановка посреди хода (автопродолжение), B3 `SIGKILL` внутри итоговой
`send()` (досылка леджера); C — голос в профиле по умолчанию, без маршрута.

Утверждения жёсткие там, где критерий двоичный (A0, A1, A2, A5, A9, B1, C1); остальное печатает факты для вердикта.

## Только для пробы

Обвязка импортирует `gateway.run.GatewayRunner`, `hermes_logging`, `hermes_cli.plugin_validate`, `tests.fakes.*`, читает
`state.db` целевого профиля напрямую (sqlite3) и трогает приватные атрибуты runner'а (`runner.adapters`) — это то, что
поднимает и осматривает шлюз, а не код плагина. В CI GitHub проба не запускается.

## Запуск

`HistoryTests` — без Hermes (Python ≥ 3.11):

```sh
cd prototypes/s7 && python -m unittest probe_s7 -k HistoryTests
```

Шлюз — нужны checkout Hermes и `python` закоммиченного окружения зависимостей (как в `prototypes/s1/README.md`); по
процессу на группу:

```sh
D=$(mktemp -d /tmp/hya-s7-XXXXXX)
cp -r prototypes/s7 "$D/"
for G in A B C; do bash "$D/s7/run.sh" <hermes-checkout> <hermes-python> "$G"; done
case "$D" in /tmp/hya-s7-*) rm -rf -- "$D" ;; esac
```

Вывод — JSON результата каждой группы (чтения, вид `state.db`, журнал после перезапуска), отчёт `plugins validate`,
пиковый суммарный RSS и итог `unittest`. Память: проба ~100 МБ + шлюз ~250 МБ; перед запуском `available` ≥ 150 МБ.

Написано под Hermes v0.23.1 (`3b42157858`); результат прогона — `docs/RECON.md`, «S7».
